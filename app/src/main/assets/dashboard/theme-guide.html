What a theme is and is not

A custom theme replaces the HTML inside #fold-inner - the part of the main screen that sits above the scroll area. You control layout, typography and colours with your own HTML and CSS. The app keeps driving everything else: the scroll tiles below, the quick-action button row, the recording banner and all the sub-pages.

A theme is not a web app. It cannot run JavaScript, load external resources or change the app's logic. It is structure and style only, with data fed in by the app.

The bundle format

A theme is a ZIP file containing three files at the root level of the archive:

FileRequiredPurpose
theme.htmlYesHTML fragment injected into #fold-inner
theme.cssYesCSS loaded for this theme
theme.jsonNoMetadata: display name, version, optional CSS-variable declarations

The ZIP filename becomes the import fallback name if theme.json has no name field. Size limit: 2 MB per file.

theme.html - structure and hooks

theme.html is a plain HTML fragment - no <html>, <head> or <body> tags, just the content you want inside #fold-inner (fold scope, the default) or #scroller (full scope - see Theme scope). The app sanitizes it before storing.

Live value hooks - data-lb

Add data-lb="key" to any element. The app sets that element's textContent to the current scooter value every 500 ms:

<div class="my-speed" data-lb="speed"></div>
<div class="my-soc"   data-lb="soc"></div>

Values are numbers (or true/false for booleans). If the scooter is disconnected, the last known value stays.

State hooks - data-lb-state

Add data-lb-state="key:classname" to toggle a CSS class based on whether a data value is truthy:

<div class="speed-box" data-lb-state="park:is-parked">

When data.park is true, the class is-parked is added; when false, it is removed.

Action hooks - data-lb-action

ValueBehaviour
speed-unlockTriple-tap to trigger the eKFV speed-unlock sequence
 
<div data-lb="speed" data-lb-action="speed-unlock"></div>

Tile registration - data-tile-id

Wrap sections with data-tile-id and data-tile-label to register them with the tile manager. Registered tiles can be shown, hidden and drag-reordered by the user:

<div data-tile-id="my-speed-block" data-tile-label="Tacho">
  <!-- speed content -->
</div>

Without data-tile-id, a section is always shown and cannot be managed.

Live-state signals on <html>

The app sets classes and CSS variables directly on the <html> element so theme CSS can react to live state without needing a data-lb-state attribute on a specific element.

Throttle-lock state

SignalTypeValuesWhen set
lb-unlockedclass on <html>present / absentPresent when the scooter is unlocked (after triple-tap or FIN rename); absent when locked
--throttle-unlockedCSS var on :root1 / 01 = unlocked, 0 = locked; useful in calc()

Updated every BLE tick (500 ms). Defaults to absent / 0 at page load.

/* Gauge scale widens when unlocked */
.gauge-scale { --scale-max: 40; }
:root.lb-unlocked .gauge-scale { --scale-max: 110; }

/* Numeric version in calc() */
.gauge-arc { stroke-dasharray: calc(var(--throttle-unlocked) * 220 + 80); }

Display unit

SignalTypeValuesWhen set
lb-mphclass on <html>present / absentPresent when the user has selected mph; absent for km/h

Set at startup and whenever the user toggles the unit in settings.

.speed-unit::after { content: 'km/h'; }
:root.lb-mph .speed-unit::after { content: 'mph'; }

/* Arc fill: 0 km/h = 0 %, 60 km/h = full arc */
.gauge-arc {
  stroke-dashoffset: calc(220 - var(--cur-speed) * 220 / 60);
}

Circular speed gauge - complete technique

A circular speed gauge is the most common full-scope theme element. This section gives you the exact SVG markup and CSS math to build one from scratch.

Geometry

The gauge uses two stacked <circle> SVG elements: a track ring (static 270° background arc) and a fill arc (shorter arc that grows with --cur-speed). The technique is stroke-dasharray / stroke-dashoffset:

stroke-dasharray="DRAW GAP"

DRAW = length of the visible segment (SVG user units). GAP = gap filling the rest of the circle.

For radius 58 in a 160×160 viewBox: circumference = 2 × π × 58 ≈ 364 px. 270° = 75% = 273 px; gap = 364 - 273 = 91 px. So stroke-dasharray="273 91" draws a 270° arc.

By default the arc starts at 3 o'clock. Rotate 135° around the centre to start at 7 o'clock: transform="rotate(135 80 80)"

Animating the fill arc with --cur-speed

dashoffset = 0 → full 273 px visible (maximum speed). dashoffset = 273 → arc fully hidden (zero speed).

.gauge-arc {
  --speed-max: 25;   /* eKFV locked: 25 km/h */
  stroke-dashoffset: calc(273 - var(--cur-speed) * 273 / var(--speed-max));
  transition: stroke-dashoffset 0.4s ease-out;
}
/* Extend scale when unlocked (lb-unlocked on <html>). */
:root.lb-unlocked .gauge-arc { --speed-max: 110; }

No JavaScript needed - --cur-speed is updated every 500 ms and CSS recalculates automatically.

Unit label toggle

Use two overlapping <text> elements toggled by opacity. display:none is unreliable on SVG text in Android WebView.

<text class="g-unit g-unit-kmh" x="80" y="100" text-anchor="middle">km/h</text>
<text class="g-unit g-unit-mph" x="80" y="100" text-anchor="middle">mph</text>
.g-unit-kmh { opacity: 1; }
.g-unit-mph { opacity: 0; }
:root.lb-mph .g-unit-kmh { opacity: 0; }
:root.lb-mph .g-unit-mph { opacity: 1; }

Inline SVG icons

No url() or http:// sources are allowed. Embed SVG directly. fill="currentColor" inherits the CSS color property.

<svg class="my-icon" viewBox="0 0 24 24" fill="currentColor" aria-hidden="true">
  <path d="M7 2v11h3v9l7-12h-4l4-8z"/>
</svg>

Transparency

These are always set for every theme. The Style Editor exposes them as "Transparenz" sliders: 0 % = fully solid (default), 100 % = fully transparent. The injected CSS variable is always opacity (1.0 = solid, 0.0 = invisible); the app converts with opacity = 1 - slider / 100.

VariableCSS valueDefaultDescription
--tile-alpha0.0-1.01.0Tile / card opacity
--btn-alpha0.0-1.01.0Button opacity
--gauge-alpha0.0-1.01.0Gauge speed-fill arc opacity
 
/* Simple opacity (whole element including text) */
[data-tile-id] { opacity: var(--tile-alpha);  }
.lb-btn        { opacity: var(--btn-alpha);   }
.gauge-arc     { opacity: var(--gauge-alpha); }

/* Background / fill transparency only (Chromium 111+ / Android WebView 111+): */
[data-tile-id] { background-color: rgb(from var(--card)    r g b / var(--tile-alpha));  }
.lb-btn        { background-color: rgb(from var(--btnfill)  r g b / var(--btn-alpha));   }
.gauge-arc     { fill:             rgb(from var(--value)    r g b / var(--gauge-alpha)); }

Gotcha: rgb(from color-mix(...) r g b / alpha) does not work on Android WebView - a color-mix() origin silently drops the alpha channel. Always use a flat CSS variable as the origin (e.g. var(--card), var(--value)), never a color-mix() result.

Label localization

The label field in a cssVars entry accepts three formats so every label is shown correctly in both EN and DE:

1. i18n key string — resolved via the app's built-in translation catalog. Use this for standard tokens (e.g. --warn, --dark-lum) whose EN and DE wording the app already supplies:

"--warn": { "default": "#FFB020", "label": "style.var.warn", "group": "accents" }

2. Bilingual object — supply your own EN and DE wording. Use this for theme-specific names not in the app catalog:

"--value": { "default": "#22CCFF", "label": { "en": "Accent (arc)", "de": "Akzent (Bogen)" }, "group": "accents" }

3. Plain string — shown as-is in both languages. Fine for brand names or labels that need no translation:

"--value": { "default": "#22CCFF", "label": "Arc accent", "group": "accents" }

Fallback chain: bilingual object → key lookup → plain string. If de is missing from the object, the en value is used as fallback.

Theme scope

By default a theme injects its HTML into #fold-inner - the fixed area above the scroll tiles. Set "scope":"full" in theme.json to replace the entire scrollable dashboard area (#scroller) instead.

{
  "name": "Full Dashboard",
  "version": "1.0",
  "scope": "full"
}

Scope "fold" (default) - replaces #fold-inner only. The scroll tiles, button row, recording banner and all sub-pages stay as-is. The tile manager continues to work on the scroll tiles.

Scope "full" - injects into #scroller and replaces the entire dashboard content. The scroll tiles are gone; only the elements your theme HTML provides are visible. All data-lb, data-lb-state and data-lb-action hooks still work as normal.

Note: with scope:"full" the tile manager is disabled for the duration of the theme. Switch back to Default to restore the built-in scroll tiles.

Full-scope DOM skeleton

No outer wrapper is needed. Sections flow in document order. Each section registers with data-tile-id so the tile manager can show, hide and reorder it.

<!-- Section 1: hero / gauge area -->
<div data-tile-id="my-hero" data-tile-label="Tacho">
  <!-- SVG gauge, SOC row, etc. -->
</div>

<!-- Section 2: data tile grid -->
<div data-tile-id="my-grid" data-tile-label="Daten">
  <!-- data cells with data-lb keys -->
</div>

<!-- Section 3: button row -->
<div data-tile-id="my-buttons" data-tile-label="Buttons">
  <!-- action buttons with data-lb-action -->
</div>
  • Sections without data-tile-id are always visible and cannot be managed.
  • The built-in scroll tiles are gone; your sections provide all data display.

Security model - no JavaScript

JavaScript does not run in themes. Enforced in two layers:

Layer 1 - import-time sanitizer (runs when the ZIP is imported and before HTML is stored). Stripped unconditionally:

  • <script> tags and their content
  • <iframe> tags and their content
  • <base> tags
  • All inline event handlers (onclick=, onerror=, etc.)
  • javascript: URIs in href, src, action
  • data: URIs in src and href
  • External http:// and https:// URLs in src and href

Layer 2 - load-time sanitizer runs again on every theme load.

Instead of JavaScript, use:

  • data-lb-state for conditional CSS classes
  • CSS @keyframes, transitions and custom properties for animation
  • data-lb-action for the built-in speed-unlock tap

How to import

Step 1 - Create the ZIP

All three files must be at the root of the archive (not inside a subfolder).

  • Windows: select all three files in Explorer, right-click - "Compress to ZIP file" (Windows 11) or "Send to - Compressed (zipped) folder"
  • macOS / Linux: zip my-theme.zip theme.html theme.css theme.json
  • Android: use a file manager that supports ZIP creation (e.g. MT Manager, ZArchiver)

Step 2 - Import in the app

  1. Transfer the ZIP to your phone.
  2. In the app: Settings - Display - Theme manager - Import theme.
  3. Pick the ZIP from your file browser.
  4. The theme appears in the list; tap Activate to apply it.
  5. The Style button opens the Style Editor for colour, brightness and font-size overrides.

To export a theme for sharing or backup: Theme manager - (tap the theme) - Export.

Portability between Laufbursche apps

The ZIP bundle format and the data-lb attribute names are a shared API across all Laufbursche apps. A theme built for one app can be imported into any other Laufbursche app that supports custom themes.

For cross-app themes: use only the data keys and CSS variables listed in this guide. Do not rely on fixed IDs or classes that belong to one app's own HTML.

Translations and language

The app runs in German or English. When the language is switched, the app re-runs the full i18n pass over your injected HTML too.

Using existing app strings

Add data-i18n="key" to any element. Fallback text between tags shows during browser testing:

<span data-i18n="dash.hero.gear.label">Gear</span>
KeyDEEN
dash.hero.gear.labelGangGear
dash.hero.battery.unitBatterie %Battery %
dash.motors.sectionMotorenMotors
dash.motor.rear.titleHINTENREAR
dash.motor.front.titleVORNEFRONT
dash.speed.vcu.unitkm/h - VCUkm/h - VCU

Adding your own translated strings

Declare a strings block in theme.json:

{
  "name": "My Theme",
  "version": "1.0",
  "strings": {
    "de": { "mtheme.speed.label": "Tempo" },
    "en": { "mtheme.speed.label": "Speed" }
  }
}

Prefix your keys with the theme name to avoid collisions. A missing key falls back to the text between the tags.

Tips and limitations

  • No external images. http:// and https:// URLs are stripped. Use CSS background-color and SVG shapes.
  • No custom web fonts. Stick to the system font stack or inline a base64 font-face (2 MB limit).
  • Default scope covers only the fold. Your theme replaces #fold-inner. Use "scope":"full" to also replace the scroll area.
  • CSS load order. theme.css loads right after dashboard.css. Prefix your class names to avoid changing app UI outside #fold-inner.
  • Content Security Policy. style-src file: - external CSS, Google Fonts and CDNs are blocked. Base64 font-face works.
  • Dark / light mode. Use var(--card), var(--text), etc. - never hardcode colours.
  • Testing. Open telemetry.html in a desktop browser. Paste your HTML into #fold-inner via DevTools, inject a <link> for your local CSS, and add a temporary <script> with dummy values - remove it before zipping.
  • Tile manager sync. Keep data-tile-label values short (under 20 characters).
  • rgb() relative colour syntax: flat origins only. rgb(from var(--card) r g b / var(--tile-alpha)) works on Android WebView 111+. rgb(from color-mix(...) r g b / alpha) does not - a color-mix() origin silently drops the alpha channel. Always use a flat CSS variable as the origin (e.g. var(--card), var(--value)), never a color-mix() result.

Was ein Theme ist und was nicht

Ein Custom-Theme ersetzt den HTML-Inhalt von #fold-inner - den Teil des Hauptbildschirms, der oberhalb des Scroll-Bereichs liegt. Layout, Typografie und Farben steuerst du mit eigenem HTML und CSS. Die App treibt den Rest weiter: die Scroll-Kacheln darunter, die Schnellaktions-Buttons, das Aufnahme-Banner und alle Sub-Pages.

Ein Theme ist keine Web-App. Es kann kein JavaScript ausführen, keine externen Ressourcen laden und die App-Logik nicht ändern. Es ist nur Struktur und Style - die Daten kommen von der App.

Das Bundle-Format

Ein Theme ist eine ZIP-Datei mit drei Dateien im Wurzelverzeichnis des Archivs:

DateiPflichtZweck
theme.htmlJaHTML-Fragment, das in #fold-inner eingefügt wird
theme.cssJaCSS, das für dieses Theme geladen wird
theme.jsonNeinMetadaten: Anzeigename, Version, optionale CSS-Variablen

Der ZIP-Dateiname wird als Fallback-Name verwendet, wenn theme.json kein name-Feld hat. Größenlimit: 2 MB pro Datei.

theme.html - Struktur und Hooks

theme.html ist ein reines HTML-Fragment - keine <html>-, <head>- oder <body>-Tags, nur der Inhalt, den du in #fold-inner (Fold-Scope, Standard) oder #scroller (Full-Scope - siehe Theme-Scope) haben möchtest. Die App bereinigt es vor dem Speichern.

Live-Wert-Hooks - data-lb

Füge data-lb="key" zu einem beliebigen Element hinzu. Die App setzt den textContent dieses Elements alle 500 ms auf den aktuellen Rollerwert:

<div class="my-speed" data-lb="speed"></div>
<div class="my-soc"   data-lb="soc"></div>

Werte sind Zahlen (oder true/false für Booleans). Wenn der Roller getrennt ist, bleibt der letzte bekannte Wert erhalten.

Zustands-Hooks - data-lb-state

Füge data-lb-state="key:klassenname" hinzu, um eine CSS-Klasse je nach Wahrheitswert eines Datenwerts zu schalten:

<div class="speed-box" data-lb-state="park:is-parked">

Wenn data.park true ist, wird die Klasse is-parked hinzugefügt; bei false wieder entfernt.

Aktions-Hooks - data-lb-action

WertVerhalten
speed-unlockDreifach-Tipp löst die eKFV-Entsperrsequenz aus
 
<div data-lb="speed" data-lb-action="speed-unlock"></div>

Kachel-Registrierung - data-tile-id

Umschliesse Abschnitte mit data-tile-id und data-tile-label, um sie beim Kachel-Manager zu registrieren. Registrierte Kacheln können vom Nutzer ein-/ausgeblendet und per Drag & Drop neu angeordnet werden:

<div data-tile-id="my-speed-block" data-tile-label="Tacho">
  <!-- Tacho-Inhalt -->
</div>

Ohne data-tile-id ist ein Abschnitt immer sichtbar und nicht verwaltbar.

Kreisförmiger Tachometer - vollständige Technik

Ein kreisförmiger Tachometer ist das häufigste Element in Full-Scope-Themes. Dieser Abschnitt liefert das exakte SVG-Markup und die CSS-Berechnungen für einen eigenen Tacho von Grund auf.

Geometrie

Der Tacho besteht aus zwei übereinander liegenden <circle>-SVG-Elementen: einem Track-Ring (statischer 270°-Hintergrundbogen) und einem Füllbogen (kürzerer Bogen, der mit --cur-speed wächst). Die Technik heißt stroke-dasharray / stroke-dashoffset:

stroke-dasharray="DRAW GAP"

DRAW = Länge des sichtbaren Segments (SVG-User-Units). GAP = Lücke für den Rest des Kreises.

Für Radius 58 in einem 160×160 viewBox: Umfang = 2 × π × 58 ≈ 364 px. 270° = 75% = 273 px; Lücke = 364 - 273 = 91 px. Also: stroke-dasharray="273 91" zeichnet einen 270°-Bogen.

Standardmäßig beginnt der Bogen bei 3 Uhr. 135° um den Mittelpunkt drehen, um bei 7 Uhr zu beginnen: transform="rotate(135 80 80)"

Animation mit --cur-speed

dashoffset = 0 → volle 273 px sichtbar (Maximalgeschwindigkeit). dashoffset = 273 → Bogen vollständig verborgen (0 km/h).

.gauge-arc {
  --speed-max: 25;   /* eKFV gesperrt: 25 km/h */
  stroke-dashoffset: calc(273 - var(--cur-speed) * 273 / var(--speed-max));
  transition: stroke-dashoffset 0.4s ease-out;
}
/* Skala bei Entsperrung (lb-unlocked auf <html>) erweitern. */
:root.lb-unlocked .gauge-arc { --speed-max: 110; }

Kein JavaScript nötig - --cur-speed wird alle 500 ms aktualisiert, CSS berechnet automatisch neu.

Einheiten-Umschalter

Zwei überlappende <text>-Elemente per opacity umschalten. display:none ist bei SVG-Text in Android WebView unzuverlässig.

<text class="g-unit g-unit-kmh" x="80" y="100" text-anchor="middle">km/h</text>
<text class="g-unit g-unit-mph" x="80" y="100" text-anchor="middle">mph</text>
.g-unit-kmh { opacity: 1; }
.g-unit-mph { opacity: 0; }
:root.lb-mph .g-unit-kmh { opacity: 0; }
:root.lb-mph .g-unit-mph { opacity: 1; }

Inline-SVG-Icons

Keine url()- oder http://-Quellen erlaubt. SVG direkt einbetten. fill="currentColor" erbt die CSS-color-Eigenschaft.

<svg class="my-icon" viewBox="0 0 24 24" fill="currentColor" aria-hidden="true">
  <path d="M7 2v11h3v9l7-12h-4l4-8z"/>

Label-Lokalisierung

Das label-Feld in einem cssVars-Eintrag akzeptiert drei Formate, damit jedes Label in EN und DE korrekt angezeigt wird:

1. i18n-Schlüssel (String) — wird über den eingebauten Übersetzungskatalog der App aufgelöst. Für Standard-Tokens (z. B. --warn, --dark-lum), deren EN- und DE-Text die App bereits enthält:

"--warn": { "default": "#FFB020", "label": "style.var.warn", "group": "accents" }

2. Zweisprachiges Objekt — eigene EN- und DE-Texte angeben. Für theme-spezifische Namen, die nicht im App-Katalog stehen:

"--value": { "default": "#22CCFF", "label": { "en": "Accent (arc)", "de": "Akzent (Bogen)" }, "group": "accents" }

3. Einfacher String — wird in beiden Sprachen unverändert angezeigt. Geeignet für Markennamen oder Labels, die keine Übersetzung benötigen:

"--value": { "default": "#22CCFF", "label": "Arc accent", "group": "accents" }

Fallback-Kette: zweisprachiges Objekt → Schlüssel-Lookup → einfacher String. Fehlt de im Objekt, wird en als Fallback verwendet.

Theme-Scope

Standardmäßig injiziert ein Theme seinen HTML-Inhalt in #fold-inner - den festen Bereich oberhalb der Scroll-Kacheln. Mit "scope":"full" in theme.json wird stattdessen der gesamte scrollbare Dashboard-Bereich (#scroller) ersetzt.

{
  "name": "Vollbild-Theme",
  "version": "1.0",
  "scope": "full"
}

Scope "fold" (Standard) - ersetzt nur #fold-inner. Scroll-Kacheln, Button-Reihe, Aufnahme-Banner und alle Sub-Pages bleiben unverändert. Der Kachel-Manager arbeitet weiterhin auf den Scroll-Kacheln.

Scope "full" - injiziert in #scroller und ersetzt den gesamten Dashboard-Inhalt. Die Scroll-Kacheln entfallen; nur die Elemente aus deinem Theme-HTML sind sichtbar. Alle data-lb-, data-lb-state- und data-lb-action-Hooks funktionieren weiterhin normal.

Hinweis: Bei scope:"full" ist der Kachel-Manager für die Dauer des Themes deaktiviert. Zurück zu "Default" wechseln, um die eingebauten Scroll-Kacheln wiederherzustellen.

Full-Scope-DOM-Gerüst

Kein äußerer Wrapper nötig. Abschnitte fließen in Dokumentreihenfolge. Jeder Abschnitt registriert sich mit data-tile-id, damit der Kachel-Manager ihn ein-/ausblenden und verschieben kann.

<!-- Abschnitt 1: Hero/Gauge-Bereich -->
<div data-tile-id="my-hero" data-tile-label="Tacho">
  <!-- SVG-Gauge, SOC-Zeile usw. -->
</div>

<!-- Abschnitt 2: Datenkachel-Raster -->
<div data-tile-id="my-grid" data-tile-label="Daten">
  <!-- Datenzellen mit data-lb-Schlüsseln -->
</div>

<!-- Abschnitt 3: Button-Reihe -->
<div data-tile-id="my-buttons" data-tile-label="Buttons">
  <!-- Aktionsbuttons mit data-lb-action -->
</div>
  • Abschnitte ohne data-tile-id sind immer sichtbar und nicht verwaltbar.
  • Die eingebauten Scroll-Kacheln entfallen; deine Abschnitte stellen alle Daten dar.

Sicherheitsmodell - kein JavaScript

JavaScript läuft in Themes nicht. Zwei Schutzebenen erzwingen das:

Ebene 1 - Import-Sanitizer (läuft beim ZIP-Import, vor dem Speichern). Bedingungslos entfernt:

  • <script>-Tags mit Inhalt
  • <iframe>-Tags mit Inhalt
  • <base>-Tags
  • Alle Inline-Event-Handler (onclick=, onerror=, etc.)
  • javascript:-URIs in href, src, action
  • data:-URIs in src und href
  • Externe http://- und https://-URLs in src und href

Ebene 2 - Load-Sanitizer läuft bei jedem Theme-Laden erneut.

Alternativen zu JavaScript:

  • data-lb-state für bedingte CSS-Klassen
  • CSS @keyframes, Transitions und Custom Properties für Animationen
  • data-lb-action für den eingebauten Entsperr-Tipp

Import-Anleitung

Schritt 1 - ZIP erstellen

Alle drei Dateien müssen im Wurzelverzeichnis des Archivs liegen (nicht in einem Unterordner).

  • Windows: alle drei Dateien im Explorer markieren, Rechtsklick - "In ZIP-Datei komprimieren" (Windows 11) oder "Senden an - ZIP-komprimierter Ordner"
  • macOS / Linux: zip mein-theme.zip theme.html theme.css theme.json
  • Android: Datei-Manager mit ZIP-Unterstützung verwenden (z.B. MT Manager, ZArchiver)

Schritt 2 - In der App importieren

  1. ZIP auf das Handy übertragen.
  2. In der App: Einstellungen - Display - Theme-Manager - Theme importieren.
  3. ZIP im Datei-Browser auswählen.
  4. Theme erscheint in der Liste; auf Aktivieren tippen.
  5. Der Style-Button öffnet den Style-Editor für Farb-, Helligkeits- und Schriftgrößen-Anpassungen.

Theme exportieren (für Teilen oder Backup): Theme-Manager - (Theme antippen) - Exportieren.

Portabilität zwischen Laufbursche-Apps

Das ZIP-Bundle-Format und die data-lb-Attributnamen sind eine gemeinsame API aller Laufbursche-Apps. Ein Theme für eine App kann in jede andere Laufbursche-App importiert werden, die Custom Themes unterstützt.

Für app-übergreifende Themes: nur die hier aufgeführten Datenschlüssel und CSS-Variablen verwenden. Keine fest codierten IDs oder Klassen aus dem App-eigenen HTML verwenden.

Die App läuft auf Deutsch und Englisch. Beim Sprachwechsel führt die App den vollständigen i18n-Durchlauf auch über dein injiziertes Theme-HTML durch.

Eigene Übersetzungen hinzufügen

Einen strings-Block in theme.json deklarieren:

{
  "name": "Mein Theme",
  "version": "1.0",
  "strings": {
    "de": { "mtheme.speed.label": "Tempo" },
    "en": { "mtheme.speed.label": "Speed" }
  }
}

Schlüssel mit dem Theme-Namen prefixen, um Kollisionen zu vermeiden. Ein fehlender Schlüssel fällt auf den Text zwischen den Tags zurück.

Tipps und Einschränkungen

  • Keine externen Bilder. http://- und https://-URLs werden aus src-Attributen entfernt. CSS-Hintergrundfarben und SVG-Formen verwenden.
  • Keine Web-Schriften. System-Font-Stack oder eine base64-Font-face-Einbettung verwenden (2-MB-Limit beachten).
  • Standard-Scope deckt nur den Fold-Bereich ab. Das Theme ersetzt #fold-inner. Mit "scope":"full" wird auch der Scroll-Bereich ersetzt.
  • CSS-Ladereihenfolge. theme.css lädt direkt nach dashboard.css. Klassen prefixen, um App-UI außerhalb von #fold-inner nicht zu verändern.
  • Content Security Policy. style-src file: - externes CSS, Google Fonts und CDNs sind blockiert. Base64-Font-Face funktioniert.
  • Dunkel-/Hellmodus. var(--card), var(--text) etc. verwenden - niemals Farben fest codieren.
  • Testen. telemetry.html im Desktop-Browser öffnen. HTML per DevTools in #fold-inner einfügen, <link> für die lokale CSS einfügen und ein temporäres <script> mit Dummy-Werten hinzufügen - vor dem Zippen entfernen.
  • Kachel-Manager. data-tile-label-Werte kurz halten (unter 20 Zeichen).
  • rgb()-Relative-Color-Syntax: nur flache Ursprünge. rgb(from var(--card) r g b / var(--tile-alpha)) funktioniert auf Android WebView 111+. rgb(from color-mix(...) r g b / alpha) funktioniert nicht - ein color-mix()-Ursprung verwirft den Alpha-Kanal lautlos. Als Ursprung immer eine flache CSS-Variable verwenden (z.B. var(--card), var(--value)), niemals ein color-mix()-Ergebnis.
